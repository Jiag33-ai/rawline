# docs/backlog

The working backlog and the task files of the 6 Oct 2026 campaign for Rawline, kept in the repository so the next session starts with them. Text only. Nothing in here is built or shipped.

Read in this order: `DISPATCH.md` (which worker next, with file names and estimates), then the task file it names (`tasks/`), then `BACKLOG.md` for the entry numbers a task cites. `FINAL.md` is the end of campaign checklist.

## What each part is
| Path | What |
|---|---|
| `DISPATCH.md` | One worker at a time on main: order, files to hand over, entries, estimates, exit checks, what Jai is asked to do |
| `FINAL.md` | End of campaign checklist: final re-check, release verification, docs, proposed CLAUDE.md lines, clean up, the report to Jai |
| `BACKLOG.md` | 507 entries (BK-001 to BK-507) by area, with milestones M1 to M7, the quick wins table, traceability to the audits and the NEXT 25 TASKS worklist. Generated: do not edit by hand, see below |
| `PHONE-TEST-S1.md` | The 10 minute phone test of the first Studio release, in plain steps for Jai |
| `probes/` | Host tests that demonstrated a finding (`FullDiskProbe.kt`: the endless save retry on a full phone); they compile against `core/studio-render` test sources and are evidence, not part of the build |
| `tasks/` | One zero-questions task file per worker (decisions made, code that was compiled and run, patches, acceptance, phone checks). Each says plainly what was run and what was only written |
| `tasks/superseded/` | The old W09 plan. Do not dispatch; its residue is `tasks/W09b-engine-residue.md` |
| `reviews/` | Read only reviews of merged code (`review-s1b.md`) with findings that became entries |
| `audits/` | The three audit documents the backlog cites (AE engine, AQ quality, AU UI) |
| `patches/` | Unified diffs the task files refer to. Each was checked with `git apply --check` against the commit named in its task file on 6 Oct 2026; run the check again before use (`git apply --check docs/backlog/patches/<name>`) |
| `src/` | The generator: `assemble.py` and `parts/` (the entries and the worklist). `BACKLOG.md` is rebuilt from them |
| `tools/final-check.sh` | The automated half of FINAL.md. It was written for the session sandbox (it compiles with a Kotlin compiler found in the Gradle distribution); in a normal clone use the Gradle tasks named in FINAL.md |

## Rules
- Entry numbers are permanent. A new entry gets the next number, in a new `src/parts/pNN.md` file with one `%%AREA X` line before each entry (see the last parts for the format).
- A status (DONE, PARTLY DONE, DESIGNED, DECIDED) is a line in `src/assemble.py` (`STATUS[...]`), with the commit that did the work. Update it when a task merges, then rebuild.
- Rebuild the backlog: `python3 docs/backlog/src/assemble.py` (writes `docs/backlog/BACKLOG.md`). The build checks that every P0 and P1 entry sits in a milestone and that numbers are unique.
- Copy and style rules of `docs/COPY.md` apply here too: Australian English, no em dashes, no model names.

## What is not here (on purpose)
Binary or large fixtures stayed in the session's scratchpad: the synthetic DNG files, golden render outputs and the compiled test jars. The seven 8 KB DNG heads that `tasks/W15-card-import.md` needs (56 KB in all) are in `docs/backlog/fixtures-dng/`: the PM hands them over with that task, or the worker rebuilds them as the file says. The 12 MB texture chart of the look 2 checks is generated by `look2_checks.py`. Every task file embeds the code and tests it needs in full, so the files here are enough to do the work.
